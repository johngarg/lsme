* LSME: The one-loop dictionary for the linear SM extensions

=lsme= is a Python package that provides one-loop matching data for the linear
SM extensions: multiplets generating dimension-6 operators at tree level in the
Standard Model Effective Field Theory (SMEFT). The package is organised into two
submodules: one for retrieving numerical coefficients and another for searching
a symbolic database. The results presented here were calculated and compiled for
the research project "Mapping the one-loop structure of linear SM extensions"
([[https://arxiv.org/abs/2412.01759][arXiv:2412.01759]]).

* Installation

You can install the package via pip:

#+begin_src bash
pip install lsme
#+end_src

* Usage

** Numerical Coefficients

The =lsme.numeric= subpackage contains Python classes for each model, with methods that return numerical values for the matching coefficients of the B-conserving operators in the dimension-6 SMEFT.

Example:

#+begin_src python
from lsme.numeric import GranadaPi7MatchingResult as Pi7

# Create an instance of the model and compute a coefficient
# All massive params are in TeV, and initialised to 1 TeV
pi7 = Pi7()

# Coeffs are methods with the same name as you get from Matchmaker 
# Flavour indices are 0-initialised
coeff = pi7.alphaOdB(0,0)

# Return a dictionary of all coefficients, keyed by WCxf Warsaw names
# [arXiv:1712.05298] but in TeV units like the methods above
coeff_dict = pi7.coeff_dict()

# Return a WCxf object in GeV units, with the scale converted to GeV,
# e.g. for running with wilson
from wilson import Wilson
w = Wilson.from_wc(pi7.to_wcxf())
#+end_src

Do not pass =coeff_dict()= directly to =wilson= or other WCxf tools: WCxf
requires dimensionful coefficients and the scale in powers of GeV. Use
=to_wcxf()=, which converts dimension-six coefficients by \(10^{-6}\) and the
dimension-five Weinberg coefficients by \(10^{-3}\).

*** Barred parameters

Parameter names ending in =bar= denote complex conjugation. For matrix-valued
parameters, the flavour indices retain the same order; in particular,
\(\mathtt{ybar}_{ij} = (\mathtt{y}_{ij})^*\), not
\(\mathtt{ybar} = \mathtt{y}^\dagger\). Any transpose needed in a Hermitian
contraction is encoded by the explicit index ordering in the matching
expressions. Thus, for general complex Yukawa matrices, set the barred
parameters with component-wise conjugation:

#+begin_src python
pi7.yubar = pi7.yu.conjugate()
pi7.ydbar = pi7.yd.conjugate()
pi7.ylbar = pi7.yl.conjugate()
#+end_src

The initialiser sets each barred matrix to the conjugate of its unbarred
counterpart, as a separate array. The two are not kept in sync: users replacing
or editing the unbarred matrices must also update the corresponding barred
parameters.

*** SM parameters and the matching scale

The SM parameters =g1=, =g2=, =g3=, =lam=, =muH=, =yu=, =yd=, =yl= and the
barred Yukawas are Wilson's pure-SM \(\overline{\mathrm{MS}}\) values at the
matching scale =scale= (in TeV, default 1 TeV), run at one loop from \(M_Z\).
Setting =scale= reloads all of them:

#+begin_src python
pi7 = Pi7()
pi7.scale = 50.0           # SM couplings now at 50 TeV
pi7.g3 = 0.9               # custom inputs go after the scale
#+end_src

- The scale must lie between \(M_Z\) and 1000 TeV; other values raise
  =ValueError= and leave the object unchanged.
- Setting =scale= overwrites manual SM inputs, so set those after the scale.
  Manual SM inputs affect matching only: =to_wcxf()= does not pass them to
  Wilson, which uses its own SM parameters when running.
- =just_running(coeff, args, reference_scale=None)= returns the explicit-log
  part at fixed couplings: the coefficient at the current scale minus its value
  at =reference_scale= (default: the model mass), with the SM couplings held at
  their current values. Models with several masses must pass =reference_scale=.

The map from Wilson's conventions,
\(\mathcal{L} \supset m_2\,\phi^\dagger\phi - \tfrac{\Lambda}{2}(\phi^\dagger\phi)^2
- (\bar q\,\Gamma_u u\,\tilde\phi + \bar q\,\Gamma_d d\,\phi + \bar l\,\Gamma_e e\,\phi
+ \mathrm{h.c.})\), to LSME's MatchMaker conventions,
\(\mathcal{L} \supset -\mu_H^2 H^\dagger H - \lambda (H^\dagger H)^2 - (y_d \bar Q D H
+ y_l \bar L E H + y_u \bar Q U \tilde H + \mathrm{h.c.})\), is

| LSME                      | Wilson                                  |
|---------------------------+-----------------------------------------|
| =g1=, =g2=, =g3=          | =gp=, =g=, =gs=                         |
| =lam=                     | =Lambda / 2=                            |
| =muH**2=                  | =-m2= (GeV\(^2\) → TeV\(^2\))           |
| =yu=, =yd=, =yl=          | =Gu=, =Gd=, =Ge= (same index order)     |
| =yubar=, =ydbar=, =ylbar= | complex conjugates of =Gu=, =Gd=, =Ge= |

Wilson's =m2= is positive, so =muH= is imaginary,
\(\mu_H = i\sqrt{m_2}\). The classes only use =(self.muH)**(2)=, which is then
exactly real and negative. This does not make coefficients real in general:
they are complex whenever other inputs are, e.g. through the CKM phase in
=yu=. The Higgs and Yukawa maps agree with the
MatchMakerEFT-to-Matchete conversion in Matchete's E_VLL example. =Gu= carries
the CKM matrix in Wilson's down-aligned basis, so =yu= is not diagonal.

The parameters are Wilson's extraction for an empty set of SMEFT coefficients;
Wilson's extraction with nonzero coefficients differs by
\(O(v^2 C^{(6)})\), beyond the retained order. One-loop SM running is a
reasonable partner for one-loop matching, but not a uniform error bound:
quartic-dependent and cancellation-sensitive coefficients can have larger
truncation errors.

**** Lookup table

=lsme.numeric.sm_running.wilson_sm_lagrangian(scale_gev)= returns Wilson's raw
parameters and =sm_parameters(scale_tev)= the mapped ones. A live Wilson
extraction takes about 25 ms per scale and carries Wilson's per-scale
integration noise. The module instead evaluates a least-squares Chebyshev fit
in \(\ln\mu\), shipped as =lsme/numeric/data/sm_table.npz= and loaded at import,
so setting the scale takes tens of microseconds and the couplings vary smoothly
with it. Its agreement with live Wilson extraction is limited by Wilson's
integration tolerance (about \(10^{-4}\) relative, \(10^{-3}\) required), not by
the fit.

The table records the Wilson version and a hash of Wilson's default SM inputs.
If either differs from the installed Wilson, or the file cannot be read, a
warning is issued and the table is rebuilt in memory (about 2 s); nothing is
written to disk. After upgrading Wilson, regenerate and commit the table:

#+begin_src sh
python scripts/build_sm_table.py
#+end_src

Above about \(10^9\) GeV Wilson's own extraction drifts from accurate one-loop
running because of its integration tolerance, and the one-loop Higgs quartic
changes sign near \(10^8\) GeV; the table therefore stops at 1000 TeV.

**** Consistency with Wilson's running

=tests/test_matching_logs.py= checks, for a selection of coefficients whose
tree-level matching vanishes, that the matching logarithms equal Wilson's
one-loop SMEFT beta functions applied to the full tree-level coefficient
vector. A coefficient is selected if its method vanishes at tree level
structurally (every term carries =onelooporder=) and numerically (exactly 0 at
several random points); the identical-current four-fermion families and entries
far below the largest beta function are excluded. With generic complex
couplings the identity holds to about \(10^{-9}\) for D, \(\Delta_1\),
\(\Delta_3\), E, \(N_D\), \(\Pi_1\), \(Q_1\), \(Q_5\), \(Q_7\), \(\Sigma_1\),
\(\Sigma_D\), \(T_1\), \(T_2\), U and \(\Xi\). The tests also record:

- *Singlet scalar S:* =lam= is the UV quartic. The trilinear shifts the EFT
  quartic at tree level, \(\lambda_{\rm EFT} = \lambda - \kappa_S^2/(2M_S^2)\),
  and the logs agree with Wilson only after this shift. Feeding the class
  Wilson's (EFT) quartic is therefore wrong at \(O(\kappa_S^2/M_S^2)\).
- *Dipole operators* (=uB=, =uW=, =uG=, =dB=, ..., =eW=): in \(\Phi\), \(\Pi_7\)
  and \(\varphi\) the exported logs are exactly minus Wilson's beta functions,
  consistent with opposite signs of the gauge couplings in the covariant
  derivative. =to_wcxf()= does not yet correct this sign. In \(\omega_1\) the
  relation holds only with its diquark couplings switched off; with them on,
  the dipole logs differ from minus Wilson's beta for reasons not yet
  established.
- *Identical-current four-fermion operators* (=ll=, =qq1=, =qq3=, =uu=, =dd=,
  =ee=): these are exported with MatchMaker's symmetric full-sum
  normalisation, whereas WCxf lists each distinct operator once. The required
  conversion is operator- and index-dependent: factors of 1 or 2 for =ll=,
  =qq1=, =qq3=, =uu= and =dd=, and 1, 2 or 4 for =ee=, which has an extra Fierz
  symmetry. Applying Wilson's own symmetry factors restores agreement with its
  beta functions. =to_wcxf()= does not yet apply them.
- *Majorana N and \(\Sigma\):* the logs carry extra terms quartic in the heavy
  coupling, i.e. quadratic in the dimension-five coefficient, which Wilson's
  dimension-six beta functions do not include. The test checks this quartic
  scaling only, not the explicit Weinberg-squared contributions.

Vector models (tree level only) and models whose couplings need a flavour
symmetry (S1, S2, \(\Upsilon\), \(\Xi_1\), \(\Omega_2\), \(\Omega_4\),
\(\omega_2\), \(\omega_4\), \(\zeta\)) are not covered by this check. Whether
the SM couplings in each formula are UV or EFT parameters at one loop
(threshold and wavefunction corrections) is not settled by it.

** Symbolic Database

The =lsme.symbolic= subpackage will provide a symbolic database that is searchable, allowing users to explore the matching data in a complementary way.  This is still under development.

* Submodules

- =lsme.numeric=: Contains models represented by classes whose methods return numerical matching coefficients.
- =lsme.symbolic=: A searchable symbolic database of the matching data.
